## 常见问题

### 应用程序无法启动

#### Windows
**问题**：ReadAny 无法启动或立即崩溃。

**解决方案**：
1. 检查是否安装了 Microsoft Visual C++ Redistributable
2. 以管理员身份运行一次以建立权限
3. 暂时禁用防病毒软件以检查冲突
4. 重新安装最新版本

#### macOS
**问题**："ReadAny 已损坏"或"无法验证开发者"错误。

**解决方案**：
1. 前往 **系统设置 → 隐私与安全性**
2. 向下滚动并点击 **仍然打开**
3. 或在终端中运行：`xattr -cr /Applications/ReadAny.app`
4. 对于 Gatekeeper 问题：`sudo spctl --master-disable`（谨慎使用）

#### Linux
**问题**：AppImage 无法运行或显示权限错误。

**解决方案**：
1. 使其可执行：`chmod +x ReadAny.AppImage`
2. 安装 FUSE：`sudo apt install libfuse2`（Ubuntu/Debian）
3. 检查依赖：`ldd ReadAny.AppImage`
4. 尝试改用 .deb 包

### 书籍无法打开

**问题**：点击书籍无反应或显示错误。

**解决方案**：
1. 验证文件未损坏（尝试在其他阅读器中打开）
2. 检查文件权限（ReadAny 需要读取权限）
3. 确保文件格式受支持
4. 尝试重新导入书籍
5. 检查文件是否有 DRM 保护（ReadAny 不支持 DRM）

### PDF 渲染问题

**问题**：PDF 显示不正确或缺少内容。

**解决方案**：
1. 记住 PDF 是固定布局；某些格式丢失是预期的
2. 如果可用，尝试提取纯文本版本
3. 尽可能使用 EPUB 格式以获得更好的阅读体验
4. 报告特定的有问题 PDF 以进行改进

### AI 对话不工作

**问题**：AI 响应失败或超时。

**解决方案**：
1. 验证 API 密钥是否正确输入在设置 → AI 中
2. 检查网络连接（Ollama 不需要）
3. 在提供商的控制台中测试 API 密钥
4. 尝试切换到不同的模型或提供商
5. 检查 API 配额/剩余积分
6. 对于 Ollama：确保服务正在运行（`ollama serve`）

### 语义搜索问题

**问题**：语义搜索结果不佳或不工作。

**解决方案**：
1. 确保书籍已向量化（检查向量化状态）
2. 等待向量化完成（大书籍需要时间）
3. 最初尝试更简单的查询
4. 验证系统有足够的 RAM 用于嵌入模型
5. 重启 ReadAny 以清除任何缓存问题

### 同步问题

**问题**：WebDAV 同步失败或显示错误。

**解决方案**：
1. 在设置 → 同步中测试连接
2. 验证 WebDAV URL 格式（如果需要，包括尾部斜杠）
3. 检查用户名/密码（如果可用，使用应用专用密码）
4. 确保 WebDAV 服务器有写入权限
5. 验证 WebDAV 服务器上有足够的存储空间
6. 检查防火墙/网络设置阻止 WebDAV

### 性能问题

**问题**：ReadAny 运行缓慢或使用过多资源。

**解决方案**：
1. 关闭其他应用程序以释放 RAM
2. 通过移除未使用的书籍减少图书馆大小
3. 如果不需要，禁用 AI 功能
4. 在设置中降低字体渲染质量
5. 定期重启 ReadAny 以清除内存
6. 更新到最新版本以获得性能改进

### TTS 不工作

**问题**：文本转语音不播放或声音不正确。

**解决方案**：
1. 检查系统音频输出设备
2. 验证系统上安装了 TTS 语音
3. 调整 TTS 速度设置（太快可能导致问题）
4. 在设置 → TTS 中尝试不同的语音选项
5. 在 Linux 上：确保安装了 speech-dispatcher

## 高级故障排除

### 日志文件

ReadAny 生成用于调试的日志文件：

**位置**：
- **Windows:** `%APPDATA%\ReadAny\logs`
- **macOS:** `~/Library/Application Support/ReadAny/logs`
- **Linux:** `~/.config/ReadAny/logs`

报告问题时包含相关日志摘录。

*注意：目前，必须从文件系统手动访问日志。应用内日志查看器计划在将来的版本中实现。*

### 安全模式

*注意：安全模式启动（按住 Shift 启动）尚未实现。此功能计划在将来的版本中实现，以帮助诊断插件/扩展冲突。*

### 重置设置

要将所有设置重置为默认值：
1. 完全关闭 ReadAny
2. 重命名/删除数据目录中的设置文件
3. 重启 ReadAny（创建新的默认设置）

**警告**：这将擦除所有自定义设置，但保留书籍和标注。

### 数据库损坏

*注意：应用内数据库修复工具尚未实现。如果您遇到数据库问题：*
1. 首先备份您的数据目录
2. 联系支持人员并提供错误详情
3. 作为最后手段：通过重新导入书籍重建图书馆

## 获取帮助

### 报告问题前

1. **首先检查此故障排除指南**
2. **在 GitHub 上搜索现有问题**
3. **更新到最新版本**以查看是否已修复
4. **收集信息**：操作系统版本、ReadAny 版本、重现步骤

### 报告错误

在 [GitHub Issues](https://github.com/codedogQBY/ReadAny/issues) 上报告问题时：

**包括**：
- ReadAny 版本（设置 → 关于）
- 操作系统和版本
- 详细的重现步骤
- 预期与实际行为
- 如果适用，提供截图
- 相关日志文件摘录

**示例报告**：
```
版本：ReadAny 1.2.3
操作系统：Windows 11 22H2
问题：打开 PDF 书籍时崩溃
步骤：1. 导入 PDF 文件 2. 点击打开 3. 应用崩溃
预期：书籍正常打开
日志：[附加相关日志摘录]
```

### 功能请求

对于新功能或改进：
1. 检查是否已在 GitHub Issues 中请求
2. 提供清晰的用例和好处
3. 如果可能，建议实现方法
4. 对讨论和替代方案持开放态度
